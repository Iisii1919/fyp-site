咁究竟有咩方法可以讀到答案？

Can the website read the answers the participant types into the embedded Google Form?

SHORT ANSWER 讀唔到 —— 唔係未做，而係瀏覽器安全模型（同源政策）刻意唔准。

<iframe> 同網站屬於唔同網域（docs.google.com vs 你個 localhost:3000 / netlify 網域），所以 JavaScript 完全讀唔到入面嘅 DOM： 讀 contentDocument 會 null、讀 contentWindow 會拋 SecurityError。呢個唔係 Google Forms 特別難搞，係所有第三方嵌入都一樣。

其實你個網站入面已經有一句註解寫住呢件事（GoogleFormEmbed.tsx 第 34 行）： 「Google 的嵌入表單不會對外送 postMessage（實測 0 則），故不採用該訊號。」 —— 即係我早就實測過，答案係零個訊息送出來。

網站端唯一拿得到嘅即時訊號，就係「同一個 src 又再 load 一次」 （即送出）。呢個訊號已經用咗喺自動跳轉上面。

咁「符合的話就直接跳轉」可唔可以做到？

要付出代價 得，但唔可以靠 Google Forms。要換成一個你控制得到嘅表單。

Google Forms 嵌入係「黑盒」——你送得入去（靠 URL 預填參數），但攞唔返出嚟。 要真正做到「答完即刻知道符唔符合、自動跳頁」，只有三條路：

方案做得到咩代價
A. 換成網站自己嘅表單 完全控制：即時驗證、符合才顯示「繼續」、答案直接寫入你自己嘅資料庫 要重寫篩選表單（4 題而已）；唔再係 Google Form，如果你要交「Google 表單」俾 HREC 就要另外交代
B. 保持 Google 表單，改用 Apps Script 做 API 表單照收，但答案可以事後自動同步／回推 仍然係事後，唔係即時；要部署 Web App + 設定權限；複雜好多
C. 現狀：手動按鈕 + 事後核對
（我而家做嘅）		 零風險、零改動、符合你原本嘅表單 按鈕可以未填完就按；靠 auditParticipantIntegrity() 事後抓漏

順便：點解 ?new=1 開唔到？

唔係網址問題 ?new=1 唔會令頁面載入失敗 —— 佢只係一個 query parameter。載入失敗係因為 dev server（port 3000）冇開。

要開嘅話，在 C:\Users\linji\edu-fpy 執行：

npm run dev

等見到 ✓ Ready in ... 之後，再開 http://localhost:3000/?new=1。

⚠️ 一個唔明顯嘅陷阱：npm run dev 一定要留喺一個 開住嘅終端機視窗裡面行。如果係由自動化工具喺背景叫起佢， 工具一交還控制權個 process 就會被整批回收 —— 之後所有頁面檢查都會「假死」 （度到 0px、click 冇反應），但其實只係 server 唔見咗。

所以「按鈕可以偷按」呢個窿，實際有幾大？

  • 參與者要刻意跳過一份 4 題、30 秒填完嘅表單，先會發生。
  • 真發生嘅話，佢唔會有篩選表單嘅回應記錄 → 你事後一定查得到。
  • 加上 Facebook／Instagram 招募本身就係自願報名，報名嘅人多數符合條件。

如果你覺得呢個窿唔可以接受，最乾淨嘅做法係 方案 A： 把 4 條題目搬入網站自己做（年齡下拉、院校下拉、兩個確認）， 咁就可以做到你原本想要嘅「符合先顯示繼續、唔符合直接擋」。 要嘅話話我知，我幫你改。
